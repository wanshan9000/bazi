# 原报告页恢复设计

## 目标

「我的报告」只承担归档、筛选与进入记录的职责。点击一条可恢复记录后，用户看到的是该测算原本的报告界面与内容，而不是另一套通用的“详情页”。查看历史报告不得重新扣点、重新生成结果或覆盖原存档。

## 当前状态

报告服务端记录已包含 `type`、`title`、`summary`、`report`、`chart`、`facts`、`createdAt` 与关联会话 ID。八字、紫微、奇门的 `report` 已符合统一 `ReportView` Schema；塔罗、称骨、姓名、风水、黄历、星座保存的是各自页面生成后的结果快照。旧浏览器迁移来的 `chart` 基础记录以及缺少完整结果的历史记录没有足够资料恢复原结果页。

## 用户体验

1. 在「我的报告」按分类选择并点击某条记录。
2. 档案协调器读取服务端记录，根据 `type` 选择对应的原报告视图。
3. 报告以“历史查看”模式展示：显示原始结果快照、保留咨询元气 AI 与关联会话入口；不显示表单、重新测算、扣点或自动保存流程。
4. 返回回到「我的报告」。删除仍在档案页提供，删除后只移除档案与关联标记，不删除 AI 会话。
5. 无法恢复的旧记录继续使用精简通用兜底页，并明确为“基础记录”。

## 恢复协议

未来新存档在既有 `report` 对象内增加不影响服务端兼容性的恢复元信息：

```js
report: {
  // 既有的完整报告结果
  ...result,
  archive: {
    version: 1,
    mode: 'native',
    sourceType: 'bazi' | 'ziwei' | 'qimen' | 'tarot' | 'huangli' | 'chenggu' | 'name' | 'fengshui' | 'horoscope',
    input: { /* 当次必要输入快照 */ },
    ui: { /* 仅影响阅读呈现的选项，例如流派、场景、牌阵 */ }
  }
}
```

存档只能保存当次已生成的结果和用户主动提交的输入；不保存令牌、口令、运行时引用或无关浏览器数据。历史记录优先读取已有 `report` 与 `chart`，不存在 `archive` 时按类型推导最小恢复参数，无法推导时降级兜底。

## 类型映射

| 类型 | 原报告视图 | 恢复依赖 |
| --- | --- | --- |
| 八字 | `BaziPage` 的完整命书区域 | `chart`、Schema `report`、流派 |
| 紫微 | `ZiweiPage` 的命盘与完整报告区域 | `chart`、Schema `report` |
| 奇门 | `QimenPage` 的起局报告区域 | 已生成 Schema `report`、问事与起局信息 |
| 塔罗 | `TarotReading` 的已揭示牌阵与解读区域 | `spread`、`cards`、`interpretation`、`question` |
| 黄历 | 个性化/通用黄历结果区域 | 已保存 `reportData`、日期、场景与可选 `chart` |
| 称骨 | 称骨结果、歌诀与解读区域 | 出生信息与完整 `result` |
| 姓名 | 姓名分析/推荐结果区域 | `analysis`、`recommendations`、可选 `chart` |
| 风水 | 房屋分析结果区域 | 已生成 `result`、布局输入与可选 `chart` |
| 星座 | 当日星座结果区域 | 已保存星座结果与日期 |
| 基础命盘 / 不完整旧档案 | 通用兜底页 | `facts`、`chart`、文本摘要 |

## 路由与组件边界

- `MyReportsPage` 继续只传报告 ID。
- `ReportArchiveDetail` 改为档案加载与恢复协调器：读取记录、判断是否可原页恢复、提供删除和关联会话操作。
- 每个报告组件新增可选 `archiveReport` / `historyMode` 输入。历史模式只消费存档快照，禁用计费、自动保存和输入表单。
- 可恢复记录保留现有 `#/report-detail?report=<id>` URL；刷新后仍由协调器重新读取存档并恢复到同一历史页面。不会把整份报告放进 URL 或浏览器本地缓存。
- 咨询入口始终使用存档 ID 建立/继续关联，保证会话归属当前报告。

## 兼容与错误处理

- 服务端字段无需迁移：`report` 已允许保存 JSON 结果快照；新增的 `archive` 为前端协议。
- 原有已存档案若缺少输入，会优先使用它已有的 `report` 和 `chart` 恢复；不满足最低条件时展示兜底内容而非临时重算。
- 若历史模式渲染失败，协调器捕获后显示该记录的通用内容与“咨询元气 AI”入口，避免整页白屏。
- 不改变档案总数、权限、积分和删除语义。

## 验证

1. 每种可恢复类型打开后不触发扣点接口与保存接口。
2. 保存的关键内容、日期、牌阵/流派/场景与原报告一致。
3. 从历史报告进入元气 AI 时携带相同报告 ID，并能从详情回看关联会话。
4. 旧基础命盘与不完整塔罗记录继续可打开，走兜底页。
5. 报告列表、刷新恢复、手机与桌面布局均回归验证。
